# Evaluation Criteria
This specification defines the criteria for evaluating the code quality of a given project.

## Quality of the code
The code quality is evaluated by the following criteria:
- **Readability**: The code is easy to read and understand.
- **Maintainability**: The code is easy to maintain.
- **Testability**: The code is easy to test.
- **Extensibility**: The code is easy to extend.
- **Reusability**: The code is easy to reuse.
- **Performance**: The code is performant.
- **Security**: The code is secure.
- **Reliability**: The code is reliable.
- **Portability**: The code is portable.
- **Usability**: The code is usable.

## Quality of the documentation
The documentation quality is evaluated by the following criteria:
- **Readability**: The documentation is easy to read and understand.
- **Maintainability**: The documentation is easy to maintain.

## Quality of the tests
The tests quality is evaluated by the following criteria:
- **Readability**: The tests are easy to read and understand.
- **Maintainability**: The tests are easy to maintain.
- **Coverage**: The tests cover the code.
- **Performance**: The tests are performant.
- **Security**: The tests are secure.
- **Reliability**: The tests are reliable.

## Quality of the project
The project quality is evaluated by the following criteria:
- **Readability**: The project is easy to read and understand.
- **Maintainability**: The project is easy to maintain.
- **Testability**: The project is easy to test.
- **Extensibility**: The project is easy to extend.
- **Reusability**: The project is easy to reuse.
- **Performance**: The project is performant.

## Detailed Checklist
- Does the code follow a standard coding style
- Does the code follow a standard naming conventions
- Does the code follow a standard directory structure
- Does the code follow a standard documentation style
- Does the code follow a standard documentation structure
- Does the code follow a standard testing style
